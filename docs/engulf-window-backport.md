# Checked CDLENGULFING windows

This scoped backport applies the checked-window idea from [TA-Lib draft #566](https://github.com/TA-Lib/ta-lib/pull/566), source `2ea9da4c800244d3e09a8b7ef30b340913e03b38`, to the pinned 0.8.3 contract. The adapter keeps its existing OHLC preparation, parameter validation, lookback, integer zero padding and null masks. It changes only the CDLENGULFING kernel selected inside `compat::call`; Python expressions and ordinary Polars `.over()` remain unchanged. Borrowing Arrow buffers already existed before this change.

The helper checks every OHLC length, requested range and output capacity before writing. High and low remain validated even though this kernel does not read their values. Open and close are cut to exactly `count + 1` rows and traversed with paired safe `windows(2)` iterators and `output.iter_mut()`. The original comparison order, including NaN and signed-zero comparisons, is retained. An unsuccessful precondition returns to the existing native validation route without writing. No unsafe code or uninitialized output access is introduced.

## Correctness and static evidence

On the authorized arm64 Mac, Python 3.12.14, NumPy 2.5.3 and Rust 1.90.0:

- All 29 release Rust tests passed; the pre-existing cost diagnostic remained ignored. Six focused tests cover pinned metadata, all 28,561 IEEE candle pairs (all five possible pattern values), ranges, short/invalid buffers, offset canaries, the compatibility route and long inputs.
- All 11,667 public tests passed separately with Polars 1.20.0, 1.44.2 and 2.1.0. The added 90 cases exercise positional, keyword and namespace expressions, eager/lazy execution, contiguous/interleaved native windows, ordered windows, chunking, empty/short inputs and missing/IEEE data in every OHLC role.
- The fresh 10,624-case, 2,167,654-value capture is byte-identical to the unchanged `56f6d5fb139031c20d86d7e818e7d267eb834295` wheel on the same runtime. Both NPZ files have SHA-256 `67a4bfcee152899b8a7058c2e3958264796453641c0118f85450b9dbeb88b41e`.
- The actual original `b2bbc26d41ec80823c8bffb0cc436a97f29911cc` C wheel on the same Mac passes the full corpus at the existing `rtol=atol=1e-10` policy (657 nonexact fields, maximum absolute finite difference 2.1543655748246238e-11). Tiny-valued cases retain the existing scale-aware absolute tolerance. Integer values, schemas, lengths, null/NaN positions and signed zeros retain their separate checks.
- A supplemental Linux-C capture compared against this Mac fails 14 cases, including generated domain candle boundaries and huge transcendental inputs. Those cross-platform results are retained as diagnostic failures; they are not accepted as numerical parity or hidden by filtering. The final candidate is byte-identical to the Mac native baseline across the entire corpus.

The exact final helper was also compiled for x86-64 using Cargo's Rust 1.90 release profile (`opt-level=3`, 16 codegen units, `lto=false`, default local ThinLTO). Its complete helper assembly contains no call instructions or panic references. A previous explicit `-Clto=off` probe is a separate configuration control and is not this evidence. Static assembly is not a performance measurement. Local checks did not collect benchmark timings. The separate source-pinned same-runner [CI comparison and independent audit](benchmarks/ci-40942396197/README.md) now support retention for dense workloads. Dense latency fell13.6–18.2% versus56 with disjoint observed ranges; grouped `.over()` comparisons overlap noise. This is not a grouped speedup claim, and the combined final candidate still requires its own complete CI comparison.
