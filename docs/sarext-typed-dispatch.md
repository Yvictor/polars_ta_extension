# Typed SAREXT and legacy signed zero

The [same-runner component diagnostic](https://github.com/Yvictor/polars_ta_extension/actions/runs/40940594703) found two actionable costs: actual original typed SAREXT kwargs decoded in 4.111 µs versus 4.697 µs for the current map (+14.24%, all12 pairs slower with disjoint process ranges), and current holder creation/eight binds/lookback took 945.525 ns with zero counted Rust allocations. Those isolated stages exclude Polars `.over()` and cannot be subtracted as exclusive costs. The map adds one counted request/456 requested bytes; it does not add eight new string allocations.

Only SAREXT's generated plugin entry changes to `Masked<SarExtParams>`. The fixed eight-field decoder reuses the numeric `Param` rules, consumes unknown values before ignoring their keys, preserves duplicate-key/error behavior, and never builds a `BTreeMap`. Defaults are exactly `0,0,.02,.02,.2,.02,.02,.2`, including integer conversion and `REAL_DEFAULT` handling. Python names/signatures, all201 plugin symbols, missing-data flags and native Polars `.over()` remain unchanged.

Small shared helpers retain the original input-count/metadata checks, broadcast/cast/null-fill/rechunk ownership, borrowed slices and length limit. They return owners before borrowing slices; there is no self-referential structure or unsafe code. Both routes validate parameters after preparation and before first-usable-row/output work. Generic kernels retain their existing calls. SAREXT uses the official public typed lookback and kernel API, with the existing full initialized-NaN output, range checks, output padding and null-mask wrapper. Borrowed Arrow inputs predate this optimization.

## The newly tested signed-zero boundary

New coverage found an inherited version difference: original C0.8.1 writes `0 - sar` at two short-side stores, whereas official C/Rust0.8.3 writes `-sar`. For positive-zero `sar`, these return +0 and -0 respectively. This is a C0.8.1→0.8.3 boundary, not a Rust-specific upstream bug. Short zeros can arise through cancellation even when every input price is nonzero. Long-side -0 is legitimate and must be preserved.

Candidate A (`8a4fc7feacc45b28929b2e7e6d1ae9919623bd2b`) is retained as an isolated comparison control: official typed Core first, followed by a written-negative-zero scan and a scalar replay on hits. That design can scan every output and replay legitimate long zeros; its portable replay may call libm FMA.

Candidate B instead invokes the same licensed, two-store-corrected scalar body exactly once. The documented public `multiversion=0.7.4` attribute dispatches a thin safe wrapper for `x86_64+fma` or the portable fallback, and the scalar body stays `inline(always)` so its existing `.mul_add` operations compile in the selected feature context. The direct dependency uses the already-resolved default/std features: no registry package, version or feature changes, and only the root dependency edge changes in Cargo.lock. No global CPU target is enabled. The feature closure includes AVX/FMA and their SSE prerequisites, all checked by the public provider before entering that clone. On ARM the portable branch uses the baseline architecture's supported instructions.

The provider internally emits guarded target-feature calls and an atomic cached selector; there is no handwritten unsafe adapter code or private TA-Lib/Polars API use. Source review must cover those generated unsafe boundaries, CPUID checks and concurrent initialization. Code-generation evidence from a matched Rust1.90 portable Linux ELF relocatable probe shows four FMA instructions and no out-of-line `fma` calls in the FMA clone; the fallback retains its legitimate libm calls. This is not evidence of the final Linux wheel or of performance. CI must verify the actual product ELF and compare all four immutable arms.

[The provenance manifest](../scripts/sarext_legacy_provenance.json) pins the0.8.3 crate checksum, official commit and complete source hashes. A regression test checks all1,409 scalar tokens after reversing only declared plumbing/formatting and the two stores. The original BSD notice is retained. The original short stores are the only arithmetic edits; legitimate long -0 remains untouched, and NaN sign/payload is outside the contract.
