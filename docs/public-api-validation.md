# Public usage and adapter follow-up

`polars_talib.aroon("high", "low")` failed with `AttributeError: 'str' object has no attribute 'ta'` before query execution. Reproduced on the published 0.2.1 macOS wheel, original commit `b2bbc26d41ec80823c8bffb0cc436a97f29911cc`, and delivered native commit `c71cd6ecb4b48601ff409926fdb0a281505e9fec`, using Python 3.12 / Polars 1.44.2. Earlier published versions have not been executed. Expression inputs and the namespace call worked. The failing-before regression is `test_aroon_column_name_regression`.

All 158 legacy module wrappers accessed `receiver.ta` directly, despite accepting `IntoExpr`. They now use the existing `parse_into_expr` helper. Strings denote columns, expressions pass through, and scalar/Series/NumPy inputs become Polars literals. The 43 newer wrappers already passed their inputs through Polars' plugin registration; their input annotations now say `IntoExpr`. Names, positional order, defaults, parameter types, output field order and numerical compatibility remain unchanged. No wrapper decorators or signature replacement are involved.

```python
import polars as pl
import polars_talib as ta

result = bars.with_columns(
    ta.aroon("high", "low").over("symbol").alias("aroon")
).unnest("aroon")  # aroondown, aroonup, both Float64
```

The coverage audit also reproduced two inherited0.2.1 issues: NumPy real-valued options survived into unsupported global-reference pickles, and Int8/UInt8/Int16/UInt16 inputs failed plugin import before Float64 casting. Recognized real numeric options now convert to builtinfloat before lookback/pickle; bool and invalid nonnumeric options retain their prior handling. Four minimal Polars dtype features enable those imports. Tests cover every real option with NumPyfloat32/64 and every indicator with all8standard signed/unsigned integer widths, including nulls, chunks, eager/lazy and native.over. These are intentional fixes, not claims that the original errors were equivalent behavior.

## Coverage inventory and independent references

`scripts/public_api_coverage.json`, generated by `scripts/generate_usage_manifest.py`, freezes each of the **201 exported indicators**, its module/namespace signatures, receiver mapping, defaults, parameter profile, output types/fields and test applicability. `test_public_coverage_inventory_cannot_silently_omit_exports` compares discovered public functions, `get_functions()`, official Python `talib.get_functions()` and the manifest. Adding an export without adding coverage fails. Imported helpers/lifecycle functions are explicitly excluded from the indicator inventory; existing packaging, discovery, lifecycle and `col()` tests cover those separately.

The official Python **TA-Lib 0.8.1** `talib.abstract.Function(...).info` provides input/parameter/output metadata. This is available today, rather than an assumed future feature. Tests compare parameter defaults, output names and required input arity. Rust **ta-lib 0.8.3** independently provides `abstract_api::FUNCS`, `FuncId::info()` and `function_description_xml()`. Generated Rust tests audit all 201 mapped functions' input arity, option order/names/types/defaults and output types, and freeze the complete 237-function Rust inventory. PERCENTILE's Rust default is **100**, while the public legacy default remains **30** through the existing compatibility adapter. The manifest lists all **36 Rust-only, unexposed** indicators; they are not advertised or silently added by this correction. Current upstream development has also changed since 0.8.3; this PR retains its pinned release and compatibility target.

For each public indicator:

- Eleven invocation forms: positional names/expressions, keyword names/expressions, mixed inputs, positional parameters, namespace positional parameters, module defaults, namespace names/keywords, and typed `ta.col()` receiver.
- Two parameter profiles: defaults and a deterministic valid nondefault profile changing all available options. The pre-existing 10,624-case migration corpus separately changes options individually, MA types, extremes and edge periods. This is not every possible combination.
- Eight input/execution scenarios: finite, leading nulls, internal nulls, internal NaNs, empty, short, multiple Arrow chunks, and unequal interleaved groups under ordinary `.over()`. Every matrix entry runs eagerly and lazily; explicit inputs use renamed source columns to catch accidental default-column binding.
- Executable default-use docstring examples for every module function and namespace method, generated from the signature manifest. Legacy examples with incorrect receivers or the `ta.pol` typo are corrected, and all 402 examples are tested against the equivalent default expression.
- Additional per-function Series, NumPy-array and scalar forms; namespace default arguments where applicable. Namespace methods requiring explicit non-receiver inputs are marked in the manifest and tested to reject omission.
- Invalid unknown keywords, excessive positional arguments, missing columns, nonscalar length mismatches where applicable, and nonnumeric option types. Existing tests and the migration corpus cover invalid period/range cases and error classes. List-valued literals, all possible coercions, every optimizer mode and every parameter combination are not promised.
- Exact form-to-form schema/length, field order, dtype, null masks, NaN positions and signed zeros. Integer outputs retain Int32 and zero padding. Official reference comparisons use rtol/atol `1e-10`, exact NaN positions and zero signs on unmasked rows. Leading missing inputs are skipped before calling the reference, preserving this package's relative index-output semantics. Null dependence masks remain covered by independent existing tests and the original-release differential; the Python reference itself has no Polars-null contract. Some Python TA-Lib functions reject empty arrays, so those cases check shape/dtype/padding through our plugin and original-release captures instead.

The migration capture now distinguishes raw annotation changes from call-contract changes: only input annotations are omitted for the latter. Raw changed function names remain visible in the report, while parameter/return annotations, argument names/order/kinds and defaults must still match. This allows the intentional Expr → IntoExpr correction without disabling API checks.

## Bounded adapter optimization

Numeric plugin options use a direct numeric Serde visitor instead of trying an integer variant before a real variant. Actual pickle fixtures preserve the previous numeric kinds, sentinels, overflow fallback and rejection behavior. This removes failed-conversion error allocations for real options. The pickle parser already owned strings for the original typed wrappers too; this change does not claim to remove those parser allocations, and the parameter BTreeMap is retained.

The native adapter borrows the aligned Series slice when broadcasting is unnecessary, fuses cast/null preparation, reuses slice descriptors after skipping leading NaNs, returns a single output without collecting a fields vector, and uses generated borrowed parameter keys rather than lowercasing each option name on every partition. Generated input/output arities now keep the prepared Series owners, slice descriptors and output descriptors in fixed stack arrays, removing three descriptor-vector allocations from the common per-partition path. Numeric output buffers remain owned, initialized allocations. Runtime arity guards and generated metadata tests verify these bounds; no unsafe storage is used. The exact-name mapping retains an owned lowercase fallback for other internal metadata names. The required compatibility scan uses the equivalent unordered bound predicate `!(abs(x) <= 1024)` in its vectorizable reduction. This catches NaNs, infinities and finite magnitudes above1024 with one comparison; the original first-row short-circuit is retained. A100,000-bit-pattern/boundary test and the original complete scan oracle check identical routing. No TA arithmetic, settings, null policy or output initialization changes.

These changes remove avoidable descriptor/key work. Series clones share Arrow storage; they do not copy numeric values. The old double `Vec` collection may already reuse its allocation through Rust's iterator specialization, so source-level collection counts are not an allocation measurement. The borrowed Float64 Arrow path predates this work. Ordinary Polars `.over()` still calls the plugin for each group, and FFI, group gather/scatter, Series/output construction and kernel work remain. No custom grouping API, list composition or ABI changes are introduced.

`src/cost_probe.rs` is an ignored release diagnostic, run explicitly by CI. It records nine batch samples of new-call/binding/lookback, generic abstract binding/call, direct kernels with a preallocated caller output, and the complete adapter at 100 / 10,000 / 1,000,000 rows for EMA/ATR. Direct kernels still include their own validation and any internal scratch. These modes are not additive stages; subtracting them does not isolate an allocator or pure dispatch cost. The full adapter mode omits Polars window scheduling/FFI and null-mask wrapper costs. It checks direct compact output against adapter alignment, and archives raw nanoseconds per call. These are diagnostic observations, not a substitute for complete-query benchmarks.

## CI performance protocol

The benchmark job rebuilds immutable original C `b2bbc26d41ec80823c8bffb0cc436a97f29911cc`, delivered native `c71cd6ecb4b48601ff409926fdb0a281505e9fec` and the exact candidate head on **one runner** with matching toolchain, portable release settings and runtime. Both native versions already initialize real outputs with NaNs. The new comparison is an adapter experiment, not another zero-versus-NaN allocation experiment.

Six fresh processes per implementation/thread setting, all six implementation-order permutations, 51 timed samples after five warmups, one and four controlled Polars threads. Workloads expose 20 individual indicator families (EMA, RSI, MACD, ATR, ADX, CCI, STDDEV, PPO, ADD, MINMAXINDEX, CDLDOJI, HMA, SUPERTREND, VWMA, MAVP, BBANDS, SAREXT, VAR, CORREL and CMOU), rather than hiding them inside mixed queries. There are 132 standard cases and141 one-thread diagnostic cases, retaining dense inputs, 100×10,000, 1,000×1,000, 10,000×100, interleaved groups, one-thread size sweep and Polars cumsum controls. Original-reference correctness gates run before timing; delivered-versus-candidate workloads and the full corpus also require exact values/signs/schema/nulls. Artifacts include raw samples, process distributions, conservative ratio envelopes, source fingerprints, commits, wheel binaries/checksums, build/dependency/toolchain logs and environment. No timing assertion gates CI: shared-runner contention remains possible, and envelopes are descriptive ranges rather than confidence intervals. Local measurements guide experiments only. The artifact also contains a per-scenario regression inventory: every median slower than C is retained, including overlapping/noisy cases, with matched Polars controls and process ranges. Six balanced rounds do not establish multiple-comparison statistical significance. The broad8d14d0d job timed out after its complete one-thread block and two four-thread rounds; those partial data are labelled accordingly. The budget is240minutes for the final composition. Final measured results and remaining regressions are linked in the PR description after final-head CI. Comparing c71 with this candidate measures cumulative adapter changes; separate CI runs cannot isolate array-only gains.

## Upstream Rust investigation

Reviewed released 0.8.3 and upstream development at `4334163d3a1f5019aa9051342316b936a4dfb994` before proposing changes:

- `ParamHolder` already uses fixed-size arrays, with no heap allocation for its bindings. Replacing hypothetical parameter vectors would duplicate nonexistent work.
- [PR #151](https://github.com/TA-Lib/ta-lib/pull/151) already handles output scratch election; development also removes MAVP's output-copy scratch.
- [PR #176](https://github.com/TA-Lib/ta-lib/pull/176) already implements hybrid stack/heap circular buffers.
- Remaining STOCH/STOCHF output-copy arms are alias paths unreachable through safe Rust's distinct mutable borrows; deleting them has no demonstrated runtime gain.

These existing improvements rule out duplicate fixes. A separate concrete equal-bound MAVP shortcut now avoids period preparation after normalization, validation and the empty-range check, while retaining the old C price-alias route. Its independent correctness and CI benchmark evidence are tracked separately in the PR description; this consumer remains pinned to0.8.3. A bounded downstream EMA/ATR typed-call experiment retained the binder/lookback/compatibility checks but showed only a tiny/noisy local improvement; it is not integrated. Bare typed-kernel timing alone overstated the actionable dispatch cost. The supported `.over()`/Arrow ABI boundaries remain in [over-dispatch.md](over-dispatch.md).

## Follow-up allocation and scan decisions

Two independently audited CI ablations tested wide-inline and compact-singleton
parameter maps against the existing BTreeMap on the same runner. Neither
established a broad query benefit; wide-inline ADD short groups regressed. Both
map experiments remain outside the shipped branch. A fixed-arity output-field
array removes one descriptor allocation but has no established standalone
throughput gain. The single-chunk input shortcut skips a metadata clone already
performed by Polars rechunk, preserving buffer offsets/validity and all casts.
It does not introduce a new borrowed Arrow-value path.

After guarded compatibility routing, VAR/STDDEV/CORREL inputs have already been
classified and CMOU always uses legacy arithmetic. Their redundant second
nonfinite scan is removed; PERCENTILE keeps its needed classification. Numerical
operations and guard thresholds remain unchanged. Expanded final CI measures
these affected families, including dense and standard native `.over()` layouts.
