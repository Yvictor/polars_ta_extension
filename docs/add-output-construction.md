# ADD: construct initialized output values once

The independently audited [56 comparison](https://github.com/Yvictor/polars_ta_extension/actions/runs/40914827113) found a dense one-million-row ADD regression against the original C implementation: 3.3660015 → 3.6465655 ms at one thread (+8.335%) and 3.4809695 → 3.8116065 ms at four threads (+9.498%), with disjoint process-median ranges. Many smaller or grouped ADD observations overlap parity or favor the Rust adapter. Those measurements identify the scenario; they do not isolate its entire cause.

The existing adapter initializes a full NaN output and then calls the 0.8.3 ADD kernel, which overwrites every produced value. The old C adapter initializes only the skipped prefix before handing reserved storage to C. The official Rust 0.8.3 public ADD and stream-fill APIs accept initialized mutable slices; neither exposes a safe output-construction API that avoids that first pass. This change does not introduce uninitialized storage or unsafe code.

The candidate keeps input-count and metadata checks, alignment, casting, null-to-NaN preparation, maximum length, parameter binding, lookback and first usable row detection. Only the parameterless, two-real-input, one-real-output ADD contract with zero lookback takes the new route. It reserves the final length, initializes the skipped prefix with NaNs, then extends the Vec with the ordered `left + right` results. All elements are initialized through safe standard-library methods. The existing missing-input wrapper applies its null masks to the result. Names, Float64 dtype, scalar broadcasting and native Polars `.over()` remain unchanged. Existing borrowed Arrow buffers are unchanged.

Unexpected helper lengths or prefix bounds decline to the original route before allocation. Once generic validation has succeeded, equal-length prepared inputs and the newly constructed output satisfy the original ADD setter/call guards. Metadata tests freeze the exact 0.8.3 ADD assumptions. Other functions retain their existing route.

On the authorized Mac, Rust 1.90.0 release, Python 3.12.14 and NumPy 2.5.3:

- All 27 release Rust tests passed; one existing cost diagnostic remained ignored. Four new tests cover metadata, 169 IEEE operand pairs across four prefix offsets, non-NaN result bits including signed zeros, empty/invalid shapes and adapter validation/name behavior.
- All 98 focused public scenarios pass on unchanged56 and this candidate. They cover positional/keyword/namespace/default expressions, eager/lazy execution, native contiguous/interleaved/ordered windows, scalar literals, all eight integer widths, Float32/64, chunking, empty/short inputs, nulls, NaNs, infinity and invalid input type.
- All 11,675 public tests pass separately on Polars 1.20.0, 1.44.2 and 2.1.0.
- The full 10,624-case, 2,167,654-value candidate capture is byte-identical to the freshly captured same-Mac56 normal wheel: NPZ SHA-256 `67a4bfcee152899b8a7058c2e3958264796453641c0118f85450b9dbeb88b41e`.
- The actual same-Mac original `b2bbc26d41ec80823c8bffb0cc436a97f29911cc` C package passes that corpus at the existing `rtol=atol=1e-10` policy (657 nonexact fields; maximum absolute finite difference 2.1543655748246238e-11; tiny-valued cases retain their scale-aware tolerance). The new focused tests also use official TA-Lib C0.8.1 array outputs as their numerical reference. The old package rejects first-argument column-name strings in many focused calls; that inherited wrapper bug was already fixed before56. These failures are retained as API evidence, not called ADD numerical regressions or presented as passing old-package public usage coverage.

No local performance timings were collected. The source-pinned [three-arm CI and independent raw audit](benchmarks/ci-40948505825/README.md) support retaining this narrow route for final composition, with **modest directional evidence, not an established latency speedup**. Short-group comparisons favor the candidate in11/12,12/12,12/12 and11/12 pairs; all ten primary process ranges overlap. The weak four-thread long-interleaved case favors it in only5/12 pairs, with median paired latency +0.68% despite a −0.77% ratio-of-medians change. Every negative and all controls remain archived.

The focused component uses explicit CLOSE+OPEN, whereas the preceding full56 run used default HIGH+LOW; these runners/operands must not be pooled or used to decompose the earlier C gap. The final combined comparison retests the original full workloads. The patch changes both output construction and ADD holder setters/dispatch, so no exclusive initialization-cost attribution is made.
