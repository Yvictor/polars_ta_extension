# Bounded CMOU checked-window experiment

This controller is a CI experiment, with candidate source/helper/public-probe pins bound to independently reviewed and published source `36a6f5dfded2330fe6df550ac3570546882e01ca`; controller activation still requires independent review. It makes no performance or Linux-codegen claim before a complete successful job and independent raw audit. The experiment does not change a public API or replace ordinary Polars `.over()` with another expression.

The four immutable products are original C081 `b2bbc26d41ec80823c8bffb0cc436a97f29911cc`, delivered Rust `56f6d5fb139031c20d86d7e818e7d267eb834295`, final consumer `e79ac0785436bbf3ba4c411d80936f8dd4ecfa24`, and the independently reviewed checked-window candidate `36a6f5dfded2330fe6df550ac3570546882e01ca`. Relative to e79 the candidate production boundary is exactly `src/compat/cmou.rs`; the CMO source, adapter, dispatch, Python wrapper, dependencies and public API are unchanged. Source-owned regression tests may be added under `tests/`. Original C and delivered56 remain controls, not substitutes for the e79-to-candidate incremental comparison.

## Fixed matrix and execution

Exactly twelve queries run: six CMOU (dense 1,000,000; dense 1,000; native grouped 100×10,000, 1,000×1,000, 10,000×100; interleaved 2,000×100); four unchanged CMO controls (dense 1,000,000; grouped 100×10,000, 10,000×100; interleaved 2,000×100); two pure Polars cum_sum controls (dense 1,000,000; grouped 10,000×100). Every indicator uses period 14. The fixture manifest and exact selector reject filtering or expansion.

Each arm/thread golden checks 9,401,000 query values. The six distinct physical inputs share historical seed 260126 prices and full OHLCV columns; period 14 arrays are unused by these indicators. Dense symbol values are all zero, distinct from the grouped 1,000×1,000 input. Interleaving preserves chronological order within each group. Exact schema, physical arrays and group warmup/written ranges are checked and the six IPC inputs retained. Equivalent indicator/control layouts reuse input bytes; each timed child constructs only its selected query.

One Ubuntu24.04 job builds all four normal release wheels sequentially with the same Rust 1.90.0 toolchain, Python 3.12.15, Polars 1.44.2, NumPy 2.5.3, maturin 1.15.0, CMake 4.4.4 and C compiler. Cargo opt3, codegen-units16, LTO=false, debug=false and empty RUSTFLAGS/CFLAGS/CXXFLAGS are explicit. Cargo LTO=false still permits compiler-local ThinLTO; no override disables it. The immutable source, actual wheel-time compile logs/fingerprints, wheel bytes, installed native bytes and release environment are retained and rechecked. No builds/corpus work runs alongside measurements.

One and four threads use fixed affinity and fresh one-case processes. The existing four-arm Williams orders are repeated three times, balancing all positions and within-round directed transitions. Each child checks its own-arm full golden, runs five warmups, measures 31 collects, then checks its final full output and digest again. Query construction, preflight serialization, golden checks, process startup and output serialization are outside timers. This is end-to-end native Polars expression latency, not an isolated CMOU kernel benchmark. Between-sample query results and allocator/cache state are part of this workload; no allocator-only cause is inferred from process page faults.

There are exactly 1,152 timed children and 35,712 latency samples. The unchanged controls and all six arm pairings are retained. Each child has a 120-second deadline and the measurement campaign a 7,200-second deadline; a timeout preserves partial logs and fails rather than changing samples or accepting an incomplete campaign. The job timeout is 180 minutes. No overlapping process or compiler-job samples are pooled.

## Correctness before timing

All four full migration captures must contain 10,624 cases and 2,167,654 checked values, with all six comparisons, API contracts, shape/dtype, field ordering, masks and integer exactness checked. Original-C floating results use the inherited documented finite tolerance; native pairs require exact finite values and signed zero, with NaN positions exact. NaN sign/payload is outside the numerical contract. No semantic difference is waived for this experiment.

The same frozen source-owned `tests/cmou_window_probe.py` is copied to the artifact and run untimed under each arm: 1,984 public cases, 147,220 output values and 408 expected invalid-period errors. It covers name/Expr/namespace inputs, eager/lazy/native grouped expressions, contiguous/interleaved groups, Float32/chunks/nulls/NaNs/infinities/signed-zero/flat/tiny/large values and empty/short/high-period lengths. All six pair comparisons require the same input fingerprints, schema, errors and masks; native pairs are exact, C pairs use rtol=atol=1e-10 and exact signs where both results are zero. The script SHA, actual native SHA, runtime, captures, comparison records and commands are bound before timing. These cases do not represent every parameter/input combination.

All eight own-arm query goldens (four products × two thread counts) are completed before any timer. Their full values, warmups and group chronology, plus the physical-input snapshots, are rechecked before and after the campaign. Timed children never write raw-input snapshots or run sibling queries.

## Actual normal Linux codegen gate

Before correctness captures or timers, each installed native Rust product's actual normal ELF is retained and inspected. The gate selects exactly the compatibility `CompatCore::cmou` kernel symbol, never the unused official083 kernel. It requires a fully decoded, executable, nonoverlapping function and one nonstack f64-store/arithmetic cyclic region. Baseline56 and e79 must have exactly three normal-path bounds guards per iteration: two input checks and one output check; alternative output branches can yield four static guard sites. The candidate must have zero reachable bounds-panic paths in that region, and no unknown call/exit. Missing, inlined, ambiguous or unfamiliar codegen fails closed; no noinline annotation or alternate proof build is introduced.

The path counter follows normal exits through the function return and counts every productive exit as well as backedge. It excludes only exits with zero output stores, requires exactly one scalar output store per completed backedge/productive exit, and rejects unknown or multiple stores. Besides scalar movsd, the frozen source’s alternative zero output can use an immediate 64-bit movq zero store. Outside-loop integer result metadata is excluded only under a narrow source/ABI role check: entry RDI remains reserved for Result<OutRange, RetCode>, with no normal-path call, register copy/clobber/use or LEA alias, and only the exact typed usize/status store forms. This is not a generic pointer-alias proof; unfamiliar compiler reshaping fails. Both retained historical normal Linux56/0eb kernels replay as212 instructions, four static guard sites, and exactly three guards on every one-store backedge, plus a zero-store loop exit. The original first counter failure is preserved in local controller-review evidence; this calibration cannot satisfy the new candidate’s actual CI gate.

The narrow CFG helper reuses the already reviewed SAR/SAREXT source-bound decoder/CFG implementation (source module SHA 04c0fe905e476d0ff33a5a1adb28f9a899bd4390677730f7a64875615d75d409); it is scoped evidence, not a complete x86 ISA/data-flow proof or proof of wrapper checks. Full actual ELF, symbol/segment/relocation tables, scoped assembly, hashes and proof reports are retained. Local ARM evidence cannot satisfy this Linux gate. If normal codegen differs, stop and inspect the retained failure without waiving or broadening the gate.

## Reporting and retention

Raw 31-sample arrays per process, chronological commands/order, process medians, paired ratios, descriptive p10–p90 envelopes, fault counters, hardware/runtime/affinity and all pairwise rows are retained. Envelopes are descriptive ranges, not confidence intervals. Every slower median, including controls and overlapping/noisy small differences, is listed. Hardware/code layout or process noise can affect unchanged CMO and Polars controls; they are not a normalization factor or causal proof. An improvement on one shape/thread setting is not a universal speed claim. Final retention requires independent raw correctness/provenance/statistics review, credible incremental benefit and explicit discussion of remaining slower-than-C cases; neither a clean test suite nor aggregate average is sufficient.
