# Selected SAR/SAREXT cold-fallback evidence

This isolated follow-up compares the original output-window candidate da9 with a candidate that adds the existing c_math::cold_arm hint only to its collective fallback. It does not modify the consumer or gate its final integration, and does not measure Polars `.over()`. The cold commit and three source hashes remain UNSET until source gates and independent review permit a separate explicit activation. The completed 7f three-arm controller, artifacts and audit remain immutable in their original branch/worktree.

Each of two Ubuntu jobs compares C TA-Lib 0.8.3 (`62021c1d14ef5499505af5547384cab509adf3fc`), current upstream Rust (`ccd3172940ed1d9daa4e7197f2265810852e8910`), the original window candidate (`da9dd99bc1780f569dfc24f35c09d4a25063162c`) and the cold-hint candidate on the same runner. Rust 1.90.0 and 1.97.0 are separate experiments; no ratios or distributions are pooled across jobs. The library declares MSRV 1.88. The root development-toolchain pin of 1.97 is not an MSRV declaration, and this workflow does not establish 1.88 performance.

All arms use fresh source builds. Rust uses portable release O3, ThinLTO, one codegen unit, no native target flags or force-dispatch hooks. The normal public typed API chooses its ordinary hardware path. C is built in release mode from the official tag. Artifact records retain exact commands, environment, compiler versions, CPU description, sources, archives, rlibs/fingerprints, executable hashes and actual executable disassembly. These provenance records bind builds but do not claim a unique instruction-by-instruction rlib-to-ELF proof.

The C source manifest hashes Git-tracked selected inputs, including the configuration template. CMake also generates an ignored include/ta_config.h; its actual bytes are separately retained and hashed. The compilation database and every compiler-emitted dependency file bind translation units, object paths and source-local inputs; unexpected untracked inputs fail. All these records are reverified before and after measurement. The generated header is recorded even when no translation unit consumes it; dependency evidence does not manufacture a consumption edge.

## Gates before timers

The 1.97 source job runs generator tests, strict generator/library Clippy, library tests/doctests, full regeneration and all 237 generated C and Rust indicator regressions. All eight nonempty source logs and exact frozen candidate hashes are verified by each measurement job. Each toolchain additionally runs all three exact Rust libraries' release tests. The code-generation inspector analyzes the actual ordinary benchmark executables before the test builds can change Cargo caches.

The bounded ELF64 x86-64 inspector reads GNU `readelf` symbol bounds/segments/relocations and GNU `objdump` instructions with raw bytes. Every scoped function must decode contiguously through its exact symbol size; missing bytes, overlapping bounds and unresolved instructions fail closed. Its iterative SCC analysis records all cyclic regions, backedges, non-stack f64 stores, floating arithmetic, reachable panic branches and unknown calls/exits. In the frozen batch-loop region, the sole mutable f64 destination is outReal; the initialization prelude separately uses an ep_temp stack buffer for MINUS_DM. A non-stack store/arithmetic cycle is an output-loop candidate, not a proof that the runtime selected it. For both 1.97 window and cold candidates, each SAR/SAREXT generic/FMA function family must have exactly one output-loop candidate with no reachable bounds panic or unknown call/exit. Unknown scope fails before timings. All scoped fallback loops and unknown calls remain in the report. Version 1.90 records its actual checks/unknowns/code growth without pretending the check-free mechanism is established there.

The bounded register proof only follows exact relocation-resolved loads of a defined local fma function into r12-r15. Must-known dataflow starts at the function entry with unknown values, merges all incoming paths, and rejects unreachable or mixed states. Every other register mention (including subregister writes, aliases, cmov and pop) kills its tag; unknown calls kill all tags. Only an exact known C-ABI fma call preserves tags under the [x86-64 SysV callee-save contract](https://gitlab.com/x86-psABIs/x86-64-ABI/-/blob/master/x86-64-ABI/low-level-sys-info.tex). Rust 1.97 compiler-builtins exports fma with [extern C](https://github.com/rust-lang/rust/blob/1.97.0/library/compiler-builtins/compiler-builtins/src/math/mod.rs); no private Rust-call preservation is assumed. The report retains the actual GOT relocation, defined function binding, loads and proven call sites. SCC analysis alone does not establish arbitrary register-value provenance or which path a runtime call selects. The separate frozen source proof supplies valid-prefix and dispatch preconditions. Actual CPU observations and the public-call capture checks supplement that proof; a scalar function's disassembly is not a measured scalar speed result.

All 60 arm/case captures complete before the first measurement child. They contain each selected full output plus 180 records: ten ranges across the fixture prefix and 17 distinct IEEE input patterns. Records preserve beginning/count, full physical buffers and NaN-payload canaries. The C driver never passes short buffers to a length-unaware C API; separate native probes exercise two short consumed inputs and a short output. All arms check three invalid ranges and applicable nonfinite options. All three native captures must match every bit. C/native non-NaN bits, signed zero, infinities, range metadata and all unwritten tails match exactly. Written NaN positions must match; every sign/payload difference is retained explicitly. No finite numerical tolerance or signed-zero waiver applies to this focused harness.

## Workload and reporting

Fifteen total typed cases comprise SAR and SAREXT, each with default and reversal-heavy parameters at 100, 10,000 and 1,000,000 rows (12 cases), plus three matching ADD sizes as unchanged controls. Six physical input snapshots are retained. Reversal coverage must include both SAREXT signs or SAR prices on both sides of the input range. Results include both function families and every control; no losing case is removed.

Each job pins the controller and its children to one available CPU. Every case uses the same four-arm Williams square three times (12 rounds). Each arm appears three times in each position; every directed adjacent arm pair appears three times. This directly compares da9 against cold on the same runner and preserves the C/CCD references; separate-host results cannot establish a layout cause. A fresh selected child performs five warmups and 31 inner samples. Fixed iterations per sample are 1,000/10/1 at the three lengths. Thus each job contains 720 children and 22,320 samples; the two jobs together contain 1,440 children/44,640 samples, without pooling their comparisons. Every timed child rechecks its selected full output against a retained C-derived golden before and after timing. Duplicate selected captures are deleted only after their hashes and sizes are recorded; complete preflight captures and goldens remain in the artifact.

The controller has a 600-second measurement budget and 30-second child timeout; workflow jobs allow 120 minutes for builds/gates. Failures retain logs and completed-child ledgers. Repetitions are not truncated to obtain a result. Reports retain all process medians, all six pairwise comparisons, including window_vs_candidate, paired ratios, round wins, descriptive envelopes and every slower median. Paired ratios and envelopes use before/after latency, so values above 1 favor the later arm; the signed latency percentage uses after/before minus 1. Envelope separation is descriptive, not a confidence interval; inner samples correlate and shared-runner interference remains. Driver dispatch and range assertions are included. Whole-child fault counts also include startup, fixture/golden I/O and warmups, so they cannot isolate allocation cost.

The only permitted native source delta from da9 is rust_lang.rs plus regenerated SAR/SAREXT files. Their frozen hashes, unchanged ADD source, all other selected source bytes and full regeneration are checked; the prior da9 four-file static source proof is retained separately. No arithmetic or guard rewrite is authorized by this experiment. Cold hints can change code generation without improving runtime; even a paired improvement does not alone establish the exact microarchitectural cause. All losses remain reportable.

No local timing constitutes performance evidence. CI results determine retention/publication, including regressions on the older compiler. No merge or release is performed by this workflow.
