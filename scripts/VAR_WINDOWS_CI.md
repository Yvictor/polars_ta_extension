# VAR checked windows: source/static-only CI

This first stage builds three pinned implementations on the same runner: official C0.8.3, current official Rust dev, and the reviewed Rust VAR window candidate. It deliberately collects **no timings**. Both the Rust harness constant and controller reject timer use. The verified pins are official dev`b0a97ddb1fa26fc8ed8b58832442db9319c40296` and fork candidate`4f73a88c554e8482fc566c2f351bca94b45946ab`; independent current-dev source review`84bda22fa087f7f8a7ab6d97d28986456ccbc75542a901648f9b2c4ffc000f9e` passed. Controller review and actual Linux fast-loop proof remain pending.

The approved prospective experiment has16 cases, three arms,12 balanced orders (all six permutations twice),31 samples after5 warmups:576 children and17,856 samples per compiler profile. Rust1.90 portable O3/LTOoff/16CGU and Rust1.97 portable O3/thinLTO/1CGU run in separate jobs and may use different CPUs. They must never be pooled or interpreted as a compiler-only comparison. Each native kernel is single-threaded on one permitted CPU. No Polars, grouping or `.over()` query gain follows from these standalone typed/abstract calls.

Cases are VAR/STDDEV typed1million rows with periods2/5/200; both typed100/10,000 rows at5; both abstract1million at5; VAR flat3.3 and STDDEV high-offset1million at5; unchanged EMA14/ADD dense controls. Period5 matches the frozen consumer benchmark's parameterless VAR/STDDEV expressions and their actual metadata defaults. This does not make C0.8.3 the consumer's old C0.8.1 implementation; their statistical algorithms differ.

Before any future timers, preserve all43,324 typed/abstract public contract calls with exact native errors/ranges/finite±0/Inf/NaN positions/tails, and the605 frozen C cases. Written NaN payload differences are diagnostic; rejected and tail poison words are exact. The C rawpointer oracle checks only10,894 valid successful calls with proved capacities; native errors/short slices are checked against unchanged Rust. All48 selected arm goldens, physical inputs, own-arm before-warmup and final-output checks remain mandatory. No serialization/checks between measured samples are proposed.

The preflight archives actual ordinary timed-route ELF files, normal rlibs and Cargo fingerprints, build commands/logs, source maps, physical frames, goldens and bounded VAR/STDDEV symbol disassembly/relocations. Typed VAR/STDDEV use black-box public function pointers in every implementation, including C, to retain and exercise the ordinary public Core body without product annotations. This adds matched call-dispatch cost and measures that route; abstract calls remain official lookup/new-holder/set/call/drop per invocation.

**Symbol extraction is not a check-removal proof.** The candidate preserves original fallback and nested reseed loops and increases code size in the Mac diagnostic. The actual Linux fast rolling loop must independently show baseline three executed per-bar guards versus candidate zero; retained fallback/reseed bounds must be distinguished. Unknown/inlined/ambiguous code generation blocks timing. After inspection, a bounded matcher with adverse fixtures and independent review is needed before a separate measurement stage. There is no universal static proof, local speedup claim, or ready-to-time flag in this first stage.

ELF/rlib relationships are source/command/hash/Cargo provenance; they are not an independent reconstruction of linker machine-code ownership. The authenticated CI run/artifact binding belongs to the sole downloader. Any future report must retain every case, all12 paired process-median ratios, raw31-sample distributions, C-relative losses, controls/noise and the code-growth risk.
