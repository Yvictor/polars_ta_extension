# VAR controlled opaque public-call comparison

This experiment compares official C0.8.3, pinned official Rust dev b0a97ddb1fa26fc8ed8b58832442db9319c40296, and reviewed VAR candidate4f73a88c554e8482fc566c2f351bca94b45946ab. It measures a controlled dynamic public-call route. Both C and Rust VAR/STDDEV typed branches explicitly cast matching public function-pointer signatures before black_box; official abstract calls retain lookup/holder/setup/call/free work. This does not establish the speed of direct/inlinable Core callers, production adapters, or Polars `.over()`.

Earlier static captures used uncast function items. They remain valid numerical evidence, but did not establish opaque typed calls or prove that the inspected standalone Core symbol was executed by the typed harness. The new route is a distinct controlled experiment. Explicit pointer types and sizes alone do not prove machine ownership.

The sample function is also called through an explicit opaque pointer immediately before each invocation. That outer dispatch occurs outside the function's Instant interval, identically for all arms, and retains a real timer root without product annotations or inline controls. The actual enabled executable must pass its timer-root/loop/call graph gate before any `--golden` timing invocation. The verifier binds main's sample pointer call and the sampled graph's intended C/Rust VAR/STDDEV pointer calls, plus the actual ordinary/reseed/fallback function code. Unknown layout, inlining, clobber or unresolved target fails closed and preserves evidence. Enabling a body or changing layout requires new proof; the disabled static binary is not transferred as timing approval.

Each profile builds all three release implementations on one runner/toolchain, pins the collector and children to one permitted CPU, and runs16 cases×3 arms×12 rounds×31 samples after5 warmups:576 fresh children/17,856 samples per profile. Each of the six arm orders occurs twice. Cases are VAR/STDDEV typed1million rows at periods2/5/200; both typed100/10,000 rows at5; both abstract1million at5; VAR flat3.3 and STDDEV high-offset1million at5; unchanged EMA14/ADD dense controls. Period5 matches the consumer benchmark defaults. Raw milliseconds are whole iteration batches:100 rows=1,000 calls/sample (100,000 input slots),10,000 rows=10 calls/sample (100,000 slots),1million rows=1 call/sample. Per-call latency requires division by iterations. Short cases repeat the same public call/buffers; they are not actual Polars groups. C0.8.3 is distinct from consumer original C0.8.1.

Rust1.90 portable O3/LTOoff/16CGU and Rust1.97 portable O3/thinLTO/1CGU are separate jobs and may have different CPUs. Never pool them or attribute differences solely to the compiler. Source-identical EMA/ADD controls can still reflect layout, optimization or machine noise.

All43,324 typed/abstract native public contracts are captured before timers, with exact statuses/ranges/finite±0/Inf/masks/untouched tails. Written NaN payloads are diagnostic; rejected/tail poison is exact. C rawpointer checks cover10,894 valid successful calls after independent safe lookback/input/capacity/range proof. Every complete C buffer and18-field native/C metadata row is retained. The605 frozen C fixtures are tested against both source-bound normal rlibs; their actual runtime values are assertions, with intersections independently replayable from public captures. Frozen Mac versus Linux NaN-sign differences are documented separately.

All48 finite selected goldens and five physical inputs precede sampling. Each fresh child checks its own complete output before warmup and after the final sample; there is no array serialization between measured samples. Buffers are allocated and poison-filled outside the interval, so allocation/initialization costs are excluded. Every final child array is preserved losslessly as gzip, including its complete range/tail bytes, raw size/SHA and compressed SHA. All31 raw timing samples, commands, balanced order, actual executable/rlib/source/Cargo/profile/hardware data and gate evidence remain available.

Reports retain every case, all12 paired process-median ratios, full31-sample distributions, all C-relative losses, faster/slower pair counts and controls. The literal paired-ratio p10>1.03/p90<0.97 labels are descriptive envelopes, not inferential confidence or permission to discard smaller consistent losses. Existing Core text growth and newly guarded cold rebuild scans are possible costs; ordinary-path guard removal does not itself prove a speedup.

The authenticated run/ZIP binding belongs to the sole downloader. Source/command/hash/Cargo relationships are provenance, not an independent reconstruction of every linker decision. No merge, release, production-call speed claim or universal equivalence is implied.
